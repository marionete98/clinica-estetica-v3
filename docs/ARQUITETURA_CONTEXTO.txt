│                                                                              │

│  Max: 20 mensagens mais recentes                                            │
│                                                                              │
│  ┌────────────────────────────────────────────────────────────────┐         │
│  │ Estrutura de Mensagem:                                         │         │
│  │ {                                                              │         │
│  │   "role": "user" | "assistant",                               │         │
│  │   "content": "texto da mensagem",                             │         │
│  │   "ts": "2025-10-20T10:00:00",                                │         │
│  │   "metadata": {                                               │         │
│  │     "intent": "schedule",                                     │         │
│  │     "agent": "scheduler",                                     │         │
│  │     "confidence": 0.95                                        │         │
│  │   }                                                           │         │
│  │ }                                                             │         │
│  └────────────────────────────────────────────────────────────────┘         │
│                                                                              │
│  Operações:                                                                 │
│  • RPUSH conv:12345 '{"role":"user",...}'  → Adiciona ao final             │
│  • LRANGE conv:12345 -10 -1                → Busca últimas 10               │
│  • LTRIM conv:12345 -20 -1                 → Mantém últimas 20              │
│  • EXPIRE conv:12345 86400                 → Renova TTL (24h)               │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘

Mensagem: "Quero agendar uma consulta para amanhã"

┌─ Passo 1: Load Context (Supervisor) ─────────────────────────────────────┐

│    {"role":"user","content":"Oi!"},                                      │

│                                                                           │

│                                                                           │

│    "intent": "schedule",                                                 │
│    "agent": "scheduler",                                                 │
│    "confidence": 0.95,                                                   │

│                                                                           │

╔═══════════════════════════════════════════════════════════════════════════════╗
║                          VANTAGENS DA ARQUITETURA                             ║
╚═══════════════════════════════════════════════════════════════════════════════╝

✅ PERFORMANCE
   • Redis < 5ms por operação
   • Contexto adaptativo (não carrega tudo)
   • Cache de contatos (87% hit rate)
   • Logs async (não bloqueia)

✅ ESCALABILIDADE
   • Redis suporta 10k+ ops/seg
   • TTL previne crescimento infinito
   • Stateless (pode escalar horizontalmente)

✅ RESILIÊNCIA
   • Graceful degradation (Redis fail → contexto vazio)
   • Circuit breakers em APIs externas
   • Fallback Supabase se cache falhar

✅ OBSERVABILIDADE
   • Logs permanentes no Supabase
   • Métricas por agent/provider
   • Tracking de custos e latência

✅ MANUTENIBILIDADE
   • Separação clara de responsabilidades
   • TTL automático (menos manutenção)
   • Documentação completa
